# Engineering

Daily code work. Promoted: every skill here ships in the plugin and is listed in the top-level README.

**User-invoked**

<!-- skills:start -->
- **[ai-rebase](./ai-rebase/SKILL.md)** — Generate improved commit messages for a git commit range using parallel subagents, without creating commits.
- **[continue-debug](./continue-debug/SKILL.md)** — Analyze the output of the most recent debug run in .scratch/debug/ and iterate with ranked hypotheses.
- **[data-engineer](./data-engineer/SKILL.md)** — Data quality verification skill for data engineering tasks. Use when working with data files, pipelines, or datasets that require validation. Triggers for: verifying file paths exist and are correct, checking file naming conventions, validating data ranges and types, auditing data quality, inspecting CSV/JSON/Parquet/Excel files, checking for nulls/outliers/duplicates, or any data ingestion and transformation quality checks.
- **[devops-engineer](./devops-engineer/SKILL.md)** — Use when making infrastructure changes (nix, docker, MCP, terraform) that need validation, when an E2E test is too expensive for the iteration cycle, when you need to isolate a testable concern from a larger integrated system, or when the user asks to run/test something — present the cost/level pyramid BEFORE executing
- **[drawio-diagram](./drawio-diagram/SKILL.md)** — Use when working with .drawio diagrams — creating new architecture diagrams from scratch, cleaning up layout, analyzing positioning, fixing alignment or spacing issues, editing connectors, checking border overlaps, or any task involving mxGraphModel XML
- **[frontend-qa](./frontend-qa/SKILL.md)** — Frontend QA workflow for Expo/React Native web apps. Use when asked to: test the app locally, verify all tabs/screens work, check if the OpenAPI schema is current, test API endpoints directly with curl/hurl, do visual QA with Playwright MCP screenshots, assess overall UI quality, or identify missing/broken UI elements. Covers: dev server startup, schema freshness check, direct API testing, Playwright MCP screenshot analysis, visual quality rubric, and critical-thinking checklist for missing elements.
- **[git-group-commit](./git-group-commit/SKILL.md)** — Group uncommitted changes into feature commits with conventional messages, and emit runnable commit artifacts. Use when the user asks to commit changes, write or improve a commit message, split work into multiple commits, or another skill needs commit messages for uncommitted changes. A single change is handled as one group. Do NOT use for PR descriptions (git-pr-message owns those).
- **[git-pr-message](./git-pr-message/SKILL.md)** — Generate a pull request description from committed groups and save it to .scratch/PR.md.
- **[implement-tdd-autonomously](./implement-tdd-autonomously/SKILL.md)** — Implement the agreed work fully autonomously using strict TDD with judgment-call rules and fail-safes. Auto-detects the right verification mode based on context.
- **[ios-qa](./ios-qa/SKILL.md)** — iOS Visual QA using Go tests + Claude Vision. Runs Go test flows that capture per-step screenshots, then evaluates each screenshot against the app's design system (docs/DESIGN.md) and Linear user story acceptance criteria. Use when asked to: visually QA the iOS app, verify screens look correct, check design compliance, do a visual regression check, or review UI after changes. Prerequisites: - Host Mac running `task ios:dev` (simulator + WDA) - WDA reachable (set WDA_URL env var, or defaults to host.docker.internal:8100)
- **[kitcut-implement](./kitcut-implement/SKILL.md)** — Reproduce a working application from a kitcut-artifact/2.0 bundle (facts.json + checks.json + requirements/ + digests/; evidence/ optional and verification-only). Use when the user provides an artifact bundle directory and wants the described app rebuilt, reproduced, implemented, or incrementally re-applied after an edit to the bundle. Do NOT use for analyzing/reviewing ordinary source repos or for creating artifacts (that is ingest's job).
- **[pm](./pm/SKILL.md)** — Project manager for backlog grooming, ticket analysis, and implementation status tracking. Use for analyzing ticket relevance, checking implementation status against codebase, splitting partially-done tickets, managing labels/assignees, and maintaining backlog health.
- **[react-native-blueprint](./react-native-blueprint/SKILL.md)** — Extract features, API contracts, and design system from React Native / Expo source code. Produces features.md, features.json, and design-system.md for re-implementation. Deterministic detection first, then LLM-enriched analysis.
- **[reverse-wireframe-ui](./reverse-wireframe-ui/SKILL.md)** — Use when creating wireframe diagrams from existing app screenshots or mockups. Triggers when user provides UI screenshots and wants drawio wireframes, component hierarchy documentation, or visual specs. Also use when reverse-engineering UI structure from images for design handoff, documentation, or re-implementation planning.
- **[tickets-status-update](./tickets-status-update/SKILL.md)** — Post a structured status update comment (DONE / WORKING ON / BLOCKED ON) to the current ticket in Linear/Jira.
- **[vector-designer](./vector-designer/SKILL.md)** — Use when creating logos, icons, SVG graphics, or any vector design work requiring visual iteration. Use when user asks to design, draw, animate, or create visual assets like logos, favicons, badges, or diagrams in SVG/PNG format. Use when adding CSS-based logo animations or brand reveal effects.
